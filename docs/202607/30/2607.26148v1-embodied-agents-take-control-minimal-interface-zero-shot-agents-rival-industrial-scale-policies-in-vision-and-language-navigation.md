## 摘要
自主具身代理必须维持一个长的决策循环，涉及在多步中感知、行动、验证和自我修正。当前系统通过特定任务的工作流或具身策略来维持这一循环。我们研究了第三种形式，即代理式具身控制，其中通用型代理自身持有循环。以零样本导航作为受控测试平台，我们仅使用单目RGB摄像头和离散动作，评估了三种软件工程代理框架。在这种严格的最小条件下，复制的默认努力配置达到70.7±3.5%的成功率（opus-5，三次运行的平均值），而fable-5在最大努力下达到78%。当训练好的航点工具作为可选能力与基本动作一同暴露时，混合fable-5代理在默认努力下达到76.7±0.6%的成功率，使用的环境步数仅为最大努力基本运行的一半，墙钟时间不到其四分之一。控制干预表明，能力主要集中在模型上：模型选择强烈改变成功率，框架效应是描述性的，强制航点接口帮助较弱的模型但可能阻碍较强的模型。然而，在更长视野的任务上性能急剧下降，而延迟和上下文增长限制了持续操作。这些结果表明代理控制在零样本导航中已具有竞争力，并且模型、框架和接口为自主具身代理提供了互补的路径。

## Abstract
Autonomous embodied agents must sustain a long decision-making loop that involves perceiving, acting, verifying, and self-correcting over many steps. Current systems sustain this loop through task-specific workflows or embodied policies. We study a third form, agentic embodied control, in which a general-purpose agent holds the loop itself. Using zero-shot navigation as a controlled testbed, we evaluate three software-engineering agent harnesses given only a monocular RGB camera and discrete actions. Under this strictly minimal condition, replicated default-effort configurations reach 70.7$\pm$3.5% success (opus-5, mean over three runs), and fable-5 reaches 78% at maximum effort. When a trained waypoint tool is exposed alongside primitives as an optional capability, the hybrid fable-5 agent reaches 76.7$\pm$0.6% at default effort, using half the environment steps and less than one quarter of the wall time of the maximum-effort primitive run. Controlled interventions show that capability is primarily model-centered: model choice strongly changes success, harness effects are descriptive, and a forced waypoint interface helps weaker models but can hinder stronger ones. Performance nevertheless falls sharply on longer-horizon tasks, while latency and context growth limit sustained operation. These results show that agentic control is already competitive in zero-shot navigation and that models, harnesses, and interfaces offer complementary paths toward autonomous embodied agents.

## 一、论文的核心问题与整体含义（研究动机和背景）
- **核心问题**：自主具身代理需要在长决策循环中感知、行动、验证和自我修正。现有系统主要通过两种方式维持循环：一是任务特定的“策略”（如NaVid等端到端训练的网络），二是人类编写的“工作流”（如NavGPT等用固定流程组合通用模型）。但这两者都将循环控制权交给外部代码或训练好的网络，模型本身并未主导交互过程。
- **研究动机**：前沿视觉语言模型（VLM）已具备跨轮感知、空间推理、进度追踪和长期工具使用能力，是否可以让模型自己掌控具身交互循环，而不是依赖导航专用脚手架？研究者希望探索一种“代理式具身控制”（agentic embodied control）形式，即通用代理自己决定何时观察、执行什么动作、如何恢复、何时停止，而非由外部环境循环或预定义工作流支配。
- **整体含义**：如果通用代理仅用最小接口（单目RGB相机+四个离散动作）就能在零样本导航任务上取得与工业级训练策略竞争的性能，那么就可以重新思考：导航能力可以更多来自模型本身，而非专门设计的导航结构。这为构建真正自主的具身代理提供了新路径。

## 二、论文提出的方法论
- **核心思想**：用通用软件工程代理框架（原本为SWE-bench等编程任务设计）驱动具身导航，模型直接控制交互循环。将导航专用脚手架全部移除，只提供最小感知-动作接口。
- **详细技术细节**：
  - **接口设计**：只暴露两个工具函数：
    - `observe()`：返回一张512×512的前向单目RGB图像，不前进环境。
    - `step(actions)`：执行一个由四种Habitat基本动作组成的序列（FORWARD 0.25m，LEFT/RIGHT 15°，STOP终止回合）。动作序列上限为每次50个基本动作，总预算500步。返回已执行基本动作数和剩余预算，但没有图像、碰撞信号或姿态信息。
  - **代理框架**：使用三个现成的软件工程代理框架：
    - `mini-swe-agent`：SWE-bench bash榜单用最小代理。
    - `Claude Agent SDK`：Anthropic提供的代理SDK。
    - `Codex CLI`：OpenAI的本地软件代理框架。均未为导航修改。
  - **系统提示**：固定任务说明，告诉代理如何交替观察和移动、成功条件、停止规则等。每回合开始一个全新会话，无跨回合状态记忆。
  - **混合接口**（可选）：在基本接口基础上增加训练好的航点预测工具（基于深度学习的航点候选），作为可选能力，允许代理在基本动作和航点之间组合使用。
- **算法流程**（文字说明）：代理每步由模型决定：先调用`observe()`获取当前视图，解析指令和上下文，然后输出一个`step()`调用（可含多个基本动作）。循环直至代理主动发出STOP或预算耗尽。模型全程控制决策顺序，框架仅负责执行工具调用、传递结果和维护会话。

## 六、论文的主要结论与发现
1. **零样本最小接口性能强劲**：通用编程代理+单目RGB+四个基本动作，在R2R-CE上默认努力平均达68-71% SR，最高78% SR，与AgenticNav（55%）和工业训练策略（如ABot-N1的71%、Qwen-RobotNav的72%）接近或相当。
2. **能力主要来自模型**：在固定框架和接口下，模型选择导致SR跨越5-72的巨大差异，是性能最敏感因素。
3. **框架效应是描述性而非因果性**：三种框架在相同模型下差别约2-7%，因服务路径不同，未能分离混杂因素。
4. **接口影响依赖模型强度**：强制航点接口对弱模型帮助大（+38 SR），对强模型几乎无帮助甚至有害（VLNVerse上SR下降4-6，碰撞率上升数倍）。**脚手架作为可选工具时效果更优**：混合接口（基本+航点）默认努力达76.7% SR，接近最大努力基本接口的78%，但步数减半、时间减四分之三。
5. **长视野任务仍是瓶颈**：RxR-CE上基本接口SR仅26%，航点接口39%；上下文长度随回合增长（中位数49k tokens），墙钟时间翻倍，使持续操作不现实。
6. **失败模式分析**：失败多为“无声”的——23/25失败回合主动声称成功，且90%的失败是路径级（从未进入3米成功区），而非终点级。主要错误类型包括：错误地绑定指代对象（12/25）、终点决策错误（6/25）、无界搜索（4/25）、几何或模拟器陷阱（3/25）。认知特征：自我诊断但无法自我纠正。
7. **真实机器人转移验证**：推理和感知能力转移成功（如条件逻辑、属性区分、多段路径），但身体感知缺失导致卡门、转向不足、空间记忆不足等问题，限制了实际部署。

## 七、优点
1. **新颖的视角**：提出“代理式具身控制”作为除策略和工作流之外的第三种方式，挑战了导航必须依赖专用脚手架的常识。
2. **极简设计**：仅用单目RGB+四个离散动作，揭示了前沿VLM中内置的导航能力，实验设计优雅。
3. **严谨的消融分析**：系统分离模型、框架、接口三轴，并单独考察推理努力和混合接口，理清了能力来源。
4. **多维度评估**：包含模拟器标准化基准（R2R-CE、RxR-CE、VLNVerse）、真实机器人部署、详细的失败分类分析，覆盖面广。
5. **混合接口实验突出**：展示了“脚手架作为可选工具而非强制通道”的设计原则，具有实践指导意义。
6. **公开透明**：提供运行注册表、系统提示、固定配置等详细信息，可复现性强；失败分析基于逐帧日志手动验证，结论可信。

## 八、不足与局限
1. **长视野性能差**：RxR-CE上SR仅26-39%，且上下文无界增长、延迟高（多个回合超过10分钟），无法支撑自主代理的持续操作。
2. **实验重复性有限**：大多数配置只运行一次，虽然Claude SDK默认努力重复3次，但其他配置（Qwen、GPT系列、航点接口等）未提供方差估计，部分结论可能受随机扰动影响。
3. **模型服务不可控**：不同模型通过不同API提供商、不同推理努力、不同缓存策略，可能引入系统偏差，论文承认比较是描述性的。
