## 摘要
主流大语言模型（LLM）服务系统主要通过分页或基数键值（KV）缓存来复用前缀工作。这种方式在高吞吐量、高并发场景下非常高效，但仅管理执行状态的一个位置片段：KV缓存。我们研究相反的体系：低延迟、小批量、设备端物理AI服务，其中交互式LLM智能体、语音系统和机器人策略在严格的响应性预算下反复分支、重置、中断和重新进入。我们引入了执行状态胶囊，这是一种在已提交边界上针对完整可恢复状态的图绑定检查点与恢复机制。FlashRT是一个白盒、面向后端的核运行时，其评估的NVIDIA CUDA后端在连续静态缓冲区上运行捕获的图计划，无需块表间接寻址。由于实时状态是一组命名的封闭缓冲区，胶囊可以对整个执行边界进行快照、恢复、分叉或回滚，包括KV、循环状态、卷积状态、MTP状态和元数据。这将复用从基于令牌地址的KV片段转向基于图绑定的执行状态边界。在RTX 5090上，胶囊恢复在存储状态级别是字节精确的，在贪心解码下令牌一致。仅KV的消融实验出现发散，表明循环状态承担了关键负载。GPU驻留的快照和恢复在亚毫秒级，相对于冷预填充的TTFT加速比从2k令牌时的3.9倍增长到16k令牌时的27倍。在Jetson AGX Thor和DGX Spark上，相同的正确性和结构性属性成立。胶囊并非替代高吞吐量KV缓存服务；它们为显式执行状态复用定义了一个互补的延迟优先服务点。

## Abstract
Mainstream LLM serving systems reuse prefix work mainly through paged or radix key-value (KV) caches. This is highly effective for high-throughput, high-concurrency serving, but it manages only one positional fragment of execution state: the KV cache. We study the opposite regime: low-latency, small-batch, on-device physical-AI serving, where interactive LLM agents, speech systems, and robot policies repeatedly branch, reset, interrupt, and re-enter under tight responsiveness budgets. We introduce execution-state capsules, a graph-bound checkpoint and restore mechanism for the complete restorable state at a committed boundary. FlashRT is a white-box, backend-facing kernel runtime whose evaluated NVIDIA CUDA backend runs captured graph plans over contiguous static buffers with no block-table indirection. Because the live state is a closed set of named buffers, a capsule can snapshot, restore, fork, or roll back the whole execution boundary, including KV, recurrent state, convolution state, MTP state, and metadata. This moves reuse from token-addressed KV fragments to graph-bound execution-state boundaries. On an RTX 5090, capsule restore is byte-exact at the stored-state level and token-identical under greedy decode. A KV-only ablation diverges, showing that recurrent state is load-bearing. GPU-resident snapshot and restore are sub-millisecond, and TTFT speedup over cold prefill grows from 3.9x at 2k tokens to 27x at 16k tokens. On Jetson AGX Thor and DGX Spark, the same correctness and structural properties hold. Capsules are not a replacement for high-throughput KV-cache serving; they define a complementary latency-first serving point for explicit execution-state reuse.

## 一、论文的核心问题与整体含义（研究动机和背景）
- **核心问题**：现有主流LLM服务系统（如vLLM、SGLang）通过分页或基数KV缓存实现高吞吐复用，但仅管理KV缓存这一部分状态，且依赖块表间接寻址，导致捕获的图无法构成自包含、可冻结的快照。这对于低延迟、小批量、设备端物理AI服务（如交互式编码代理、语音前端、机器人策略）而言，响应性严重不足，频繁的会话重置、分支、中断和重新进入需要完整状态恢复，而非仅KV复用。
- **整体含义**：物理AI服务需要一种显式管理完整执行状态的机制，将复用单元从“令牌寻址的KV片段”转变为“图绑定的执行状态边界”。本文提出执行状态胶囊（Execution-State Capsules），作为与高吞吐KV缓存互补的低延迟服务点，专为单流/少流、延迟优先的设备端场景设计。

## 二、论文提出的方法论
- **核心思想**：通过连续静态缓冲区上的图计划捕获整个前向传播过程，消除块表间接寻址，使实时状态成为一组固定命名的缓冲区。在此基基础上，将已提交边界处的完整状态冻结为执行状态胶囊，支持快照、恢复、分叉、回滚四个动词。
- **关键技术细节**：
  - **FlashRT运行时**：白盒、面向后端的核运行时（评估NVIDIA CUDA后端）。热路径是捕获的图计划（单CUDA图发射或命名子图DAG），运行在连续静态缓冲区上，无块表间接寻址。手写内存密集型算子，GEMM封装后端厂商库。
  - **胶囊内容**：对于混合模型，包括线性注意力循环状态、卷积状态、MTP尾和紧凑缓存、最后隐藏状态、边界元数据（位置、令牌前缀摘要），以及KV区域（全注意力KV和长上下文去量化有效结尾）。
  - **操作**：快照（冻结缓冲区集到GPU/主机/磁盘）、恢复（复制字节回缓冲区并重放已捕获图，不重新捕获）、分叉（从单一胶囊创建N个独立会话）、回滚（恢复到会话早期边界）。恢复是负载核心动词，机制是小固定序列（摘要检查、GPU提升、字节复制、元数据重绑定、图重放）。
  - **代价模型**：将共享前缀复用从计算绑定的重计算转为带宽绑定的状态复制。恢复复杂度为Θ(字节)，远小于冷预填充的计算复杂度O(L)。
  - **正确性三层次**：（1）字节恢复——存储缓冲区逐字节还原；（2）状态完备性——胶囊包含下一步依赖的所有活缓冲区，通过对抗性测试验证（完全覆盖后恢复输出不变）；（3）端到端等价性——贪心解码令牌一致。特别指出块对齐条件：对于分块线性注意力，边界必须与块大小对齐才能精确恢复循环状态。
  - **统一契约**：最小执行契约（三个句柄类型、一个不透明形状键、严格机制非策略边界）覆盖LLM代碼代理、机器人RL回滚、规划器-执行器切换三种场景。

## 六、论文的主要结论与发现
- **胶囊恢复是字节精确、令牌一致的**，贪心解码下与冷全预填充完全一致。KV-only恢复首个令牌即发散（97.9%错配），证明循环状态关键。
- **冷预填充TTFT加速比随前缀长度扩大**：RTX 5090上2k时3.9倍，16k时27倍；Jetson Thor上达到9–76倍，因边缘设备冷预填充更贵。
- **胶囊操作亚毫秒级**：GPU内快照和恢复约0.3–1.2ms，恢复+附加后TTFT平坦（51–57ms），无论前缀长度。
- **与vLLM-APC对比**：在RTX 5090上，胶囊平坦（约53ms）低至vLLM-APC命中（76–143ms）之下，且当工作集超过VRAM容量时vLLM-APC崩溃为冷（519–2057ms），但胶囊保持平坦。在Thor/Spark上，由于统一内存无驱逐，vLLM-APC不崩溃但TTFT仍比胶囊高3–4倍。
- **统一契约有效性**：同一机制跨越LLM编码代理的暖启动、机器人RL回合重置、规划器-执行器零拷贝切换，证明机制通用性。
- **块对齐条件**：确保分块线性注意力循环状态精确恢复，否则FP8舍入误差累积会破坏令牌一致。

## 七、优点
- **方法创新**：将执行状态作为一等管理对象，而非仅KV缓存。通过连续静态缓冲区图捕获，同时实现低延迟和状态可冻结性，两个特性源自同一设计选择。
- **结构透明**：定义三层正确性（字节恢复→状态完备→令牌等价），并识别块对齐条件，对混合注意力模型特别重要。
- **实验设计严谨**：公平对比vLLM（最佳配置、同模型），诚实报告SGLang限制；分离运行时底层提速与胶囊机制增益；多设备复制验证泛化性；消融实验证明循环状态不可或缺。
- **开源与可复现**：代码和可复现命令已发布（github/flashrt-project/FlashRT）。
- **实用价值**：面向物理AI场景（编码代理、机器人、语音），解决高吞吐栈无法优化的间歇性会话问题，提供显式策略控制而非自动缓存。

## 八、不足与局限
- **适用场景受限**：仅适用于低并发、小批量、形状受限的工作负载。高并发、动态形状场景下，静态缓冲区图捕获不灵活，需用分页/基数缓存。
- **未验证多轮生产服务**：论文为微基准测试，多轮代理服务器（自动前缀匹配、OpenAI风格历史客户端、图缓存鲁棒性）有工程未解决问题，列为未来工作。
- **未完成长KV模式**：“TQ”模式尚未接通，快照会失败而非生成部分胶囊。
- **无端到端机器人评估**：动作回放和重置为机制验证，未报告机器人任务成功率和安全性，需今后在真实机器人上评估。
- **TTS管线并非端到端**：LLM+TTS延迟为组合估计而非共同驻留测量，因VRAM限制无法同时加载27B模型和TTS。
- **对称性**：论文仅比较一个混合模型（Qwen3.6），未报告其他架构（如纯Transformer或纯状态空间模型）。高吞吐基线（vLLM）的decode速度未直接比较，因MTP差异而有意排除，但可能影响读者对整体吞吐的理解。
- **策略控制开销**：胶囊需要显式策略（固定、提升、驱逐），增加了服务层复杂度，而vLLM/SGLang的自动缓存策略通常开箱即用。
