## 摘要
主流LLM服务系统主要通过分页或基数键值（KV）缓存重用前缀工作。这对于高吞吐量、高并发服务非常有效，但它仅管理执行状态的一个位置片段：KV缓存。我们研究相反的方向：低延迟、小批量、设备端物理AI服务，其中交互式LLM智能体、语音系统和机器人策略在严格的响应预算下反复分支、重置、中断和重新进入。我们引入了执行状态胶囊，这是一种在提交边界处对完整可恢复状态进行图绑定检查点和恢复的机制。FlashRT是一个面向白盒的、后端的核运行时，其经过评估的NVIDIA CUDA后端在连续静态缓冲区上执行捕获的图计划，无需块表间接寻址。由于活动状态是一组封闭的命名缓冲区，胶囊可以快照、恢复、分支或回滚整个执行边界，包括KV、循环状态、卷积状态、MTP状态和元数据。这将重用从以令牌寻址的KV片段转移到以图绑定的执行状态边界。在RTX 5090上，胶囊恢复在存储状态级别是字节精确的，在贪婪解码下是令牌一致的。仅KV的消融实验出现分歧，表明循环状态承担了重要负荷。GPU驻留的快照和恢复时间低于毫秒，相对于冷预填充的TTFT加速从2k令牌时的3.9倍增长到16k令牌时的27倍。在Jetson AGX Thor和DGX Spark上，相同的正确性和结构特性成立。胶囊并非替代高吞吐量KV缓存服务；它们为显式执行状态重用定义了一个互补的优先延迟服务点。

## Abstract
Mainstream LLM serving systems reuse prefix work mainly through paged or radix key-value (KV) caches. This is highly effective for high-throughput, high-concurrency serving, but it manages only one positional fragment of execution state: the KV cache. We study the opposite regime: low-latency, small-batch, on-device physical-AI serving, where interactive LLM agents, speech systems, and robot policies repeatedly branch, reset, interrupt, and re-enter under tight responsiveness budgets. We introduce execution-state capsules, a graph-bound checkpoint and restore mechanism for the complete restorable state at a committed boundary. FlashRT is a white-box, backend-facing kernel runtime whose evaluated NVIDIA CUDA backend runs captured graph plans over contiguous static buffers with no block-table indirection. Because the live state is a closed set of named buffers, a capsule can snapshot, restore, fork, or roll back the whole execution boundary, including KV, recurrent state, convolution state, MTP state, and metadata. This moves reuse from token-addressed KV fragments to graph-bound execution-state boundaries. On an RTX 5090, capsule restore is byte-exact at the stored-state level and token-identical under greedy decode. A KV-only ablation diverges, showing that recurrent state is load-bearing. GPU-resident snapshot and restore are sub-millisecond, and TTFT speedup over cold prefill grows from 3.9x at 2k tokens to 27x at 16k tokens. On Jetson AGX Thor and DGX Spark, the same correctness and structural properties hold. Capsules are not a replacement for high-throughput KV-cache serving; they define a complementary latency-first serving point for explicit execution-state reuse.

## 一、论文的核心问题与整体含义（研究动机和背景）
- **主流范式与矛盾**：现有LLM服务系统（如vLLM的PagedAttention、SGLang的RadixAttention）主要通过分页或基数KV缓存重用前缀，管理的是位置可寻址的KV缓存片段，这对于高并发、高吞吐量场景非常有效。但在**设备端、低延迟、小批量的物理AI服务**（如交互式编码智能体、语音前端、机器人策略）中，系统需要在严格响应预算下频繁进行分支、重置、中断和重新进入，此时主流方法的吞吐优化机制难以发挥优势。
- **核心问题**：物理AI服务的限制性问题是：不仅需要共享前缀的KV重用，更需要系统在交互变化（新轮次、分支、中断、重新进入）后能快速恢复有效的继续状态。而现有KV缓存仅管理KV这一部分状态，没有暴露整个执行边界的控制面。
- **研究含义**：论文提出一种互补的服务设计点——**执行状态胶囊（Execution-State Capsule）**，将重用单位从令牌寻址的KV片段转变为图绑定的执行状态边界，为低延迟、单流、设备端交互提供显式状态复用机制。

## 二、论文提出的方法论
- **核心思想**：设计一个两层的系统：底层为低延迟运行时子层FlashRT，上层为执行状态胶囊机制。
  - **FlashRT**：一个白盒、面向后端的核运行时（评估NVIDIA CUDA后端），其热路径是在连续静态缓冲区上执行的捕获图计划，**没有块表间接寻址**。这使得整个前向传播的活状态是一组固定的命名缓冲区，是冻结、恢复、分支和回滚的基础。
  - **执行状态胶囊**：在提交边界处冻结完整的活缓冲区集合（包括KV、线性注意力循环状态、卷积状态、MTP状态、元数据）。提供四个动词：快照（snapshot）、恢复（restore）、分支（fork）、回滚（rollback）。
- **关键技术细节**：
  - **图绑定执行状态**：不是指整图，而是指该路径活状态所依赖的封闭缓冲区集合。图粒度是性能选择，不是抽象约束。
  - **代价模型**：冷前缀预填充是计算密集型，复杂度∝前缀长度L；胶囊恢复仅需带宽绑定复制Θ(L)字节，远快于预填充。速度差随L增大而扩大。
  - **实现**：快照和恢复都通过设备间内存复制（GPU内为子毫秒级），无需重捕获图。
  - **对齐条件**：对于分块线性注意力，快照必须在块对齐边界进行（P’ = ⌊P/C⌋·C），否则恢复+追加会引入块分裂，导致FP8舍入误差累积使输出不一致。
  - **正确性三层次**：字节恢复→状态完备性→端到端令牌等价。通过对抗性测试验证（脏状态后恢复仍令牌一致）。

## 六、论文的主要结论与发现
- **核心结论**：通过将推理会话视为可检查点、可分支的对象（而非基于分页缓存的流），可以得到服务系统的第三个管理对象。FlashRT通过捕获整个前向为连续静态缓冲区上的图计划，使提交状态成为固定缓冲区集；将其冻结为执行状态胶囊，将前缀重用从计算密集型重算转变为带宽绑定的复制重建，并将分支和回滚变为一阶操作。
- **主要发现**：
  1. FlashRT的冷TTFT比vLLM低2.6–2.8倍，且尾部延迟紧凑（p99几乎等于p50），满足硬响应性要求。
  2. 胶囊恢复是子毫秒级（GPU驻留），胶囊TTFT稳定在约53 ms（4096 token前缀），且前缀越长加速比越大（从2k的3.9×到16k的27×）。
  3. 仅恢复KV（丢弃循环/卷积状态）会导致第一个令牌就出现97.9%的令牌错误，证明循环状态承担重要负荷，胶囊必须是完整状态对象。
  4. 在体现代理场景（循环多个上下文）中，vLLM APC在5090上在约16k token工作集后缓存碰撞消失，TTFT回退到冷预填充（519 ms），而胶囊始终平坦约50 ms。
  5. 在Thor和Spark上同样验证了相同性质，冷→胶囊加速比分别达76×和33×（因边缘设备冷预填充更长）。
  6. 该机制跨越模型类型（LLM、TTS、VLA扩散策略），只需最小执行契约。机器人动作重放字节精确（余弦1.0）。
  7. 胶囊不要求改变稳态解码；仅影响预填充/TTFT。

## 七、优点
- **方法创新性**：提出将执行状态边界的完整快照作为一阶管理对象，而非仅KV片段。这解决了当前主流系统无法自然支持分支、回滚、循环状态复用的问题。
- **设计统一性**：同一静态缓冲区图选择同时带来低延迟（无间接寻址、重放字节一致）和状态可冻结性——两个特性不是独立功能，而是同一设计选择的两方面。
- **跨域一致性**：一个执行契约和机制同时服务于LLM编码智能体的热启动、机器人RL展开的回合重置、规划-执行器切换，展示了统一抽象的力量。
- **严格正确性验证**：定义了三级正确性（字节、状态完备、端到端令牌等价）并通过对抗性测试验证，包括脏状态恢复和块对齐条件。
- **实验覆盖全面**：在三个不同硬件设备上重复实验，且包含关键消融（KV-only对比）、工作负载模型（体现代理循环）及TTS运行时检查。
- **诚实澄清局限**：明确澄清胶囊不是高吞吐KV缓存的替代品；标注SGLang相同模型延迟未做（量化不支持）；未来工作包括多轮代理服务、在线机器人评估。
- **代码释放**：提供完整可重现命令和人工制品（GitHub: flashrt-project/FlashRT）。

## 八、不足与局限
- **实验范围限制**：
  - 仅单流并发1，无高并发或分布式集群实验，因此无法评估更通用场景。
  - 所有测量为离线微基准，未涉及生产多轮智能体服务或实际机器人部署。
  - 机器人部分仅为离线图机制测试（动作重放余弦1.0），无在线任务成功率和安全性评估。
- **基准对比局限**：
  - vLLM对比在混合模型APC上标注为“实验性”，可能未优化，导致APC表现可能低估。
  - SGLang无相同模型延迟对比（因量化支持问题），削弱了与基数前缀管理对象的结构性对比力度。
  - 作者虽诚实避免不公平比较，但缺少直接数字或近似估算。
- **实现局限**：
  - 胶囊是二进制状态blob，绑定精确的权重、量化、内核版本和图桶，不可跨版本移植。
  - 静态缓冲区图捕获需要有界形状变体集合，不适合高度可变形状的多流场景。
  - 长“TQ”KV模式未连接；快照失败会大声报错而非产生部分胶囊。
  - 容器存储/转移仅在单节点，无分布式KV设计。
- **潜在偏差风险**：
  - 所有实验由单一作者进行，缺乏独立第三方验证。
  - FlashRT与胶囊是同一系统，作者可调整优化细节；与vLLM的对比可能存在未控制的实现差异（如vLLM可能未针对低延迟最优化）。
  - MTP解耦排除可能有利于FlashRT（它使用MTP而vLLM未使用），论文明确为公平性排除，但仍需注意。
- **应用限制**：
  - 物理AI场景中胶囊仅恢复计算状态，不支持世界状态回滚，安全恢复依赖上层有效性检查。
  - 需要固定部署环境（权重、量化、图桶相同），否则胶囊失效。
  - 在统一内存设备（Thor/Spark）上，vLLM APC不会退化，胶囊优势仅体现在绝对延迟较低，而非避免退化。
